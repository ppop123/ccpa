# CCPA Architecture

CCPA is a single-process TypeScript service. It exposes local OAuth-backed
Claude, Codex, and optional Grok access through OpenAI-compatible HTTP routes,
plus an optional uploaded-file CLI agent execution surface.

Use [docs/AGENT_GUIDE.md](docs/AGENT_GUIDE.md) for task-oriented usage. This
file defines implementation boundaries and the shortest useful repository map.

## Layers

1. **Process and configuration**
   - `src/index.ts` selects login or server mode.
   - `src/config.ts` loads YAML, applies defaults, and normalizes provider,
     timeout, rate-limit, cloaking, and Agent Runs settings.
   - `src/startup.ts` permits startup when a provider is ready or Agent Runs is
     explicitly enabled.
2. **HTTP composition**
   - `src/server.ts` owns authentication, JSON limits, optional rate limiting,
     route registration, health, admin status, and monitoring endpoints.
   - `/v1` and `/admin` require an API key. `/health` is deliberately public
     and non-sensitive.
3. **Provider adapters**
   - `src/providers/claude.ts`, `codex.ts`, and `grok.ts` expose a shared model
     API shape while retaining provider-specific auth and upstream behavior.
   - `src/providers/router.ts` selects the provider from the requested model.
   - `src/proxy/` contains Claude translation, passthrough, retry, cooldown,
     streaming, and upstream error handling.
4. **Agent Runs**
   - `src/agents/bundle.ts` validates uploaded file contents and safe relative
     paths.
   - `src/agents/runners.ts` builds fixed CLI commands; clients cannot pass
     arbitrary runner flags.
   - `src/agents/manager.ts` creates isolated run directories, records a Git
     baseline, enforces concurrency/timeouts, collects diffs, and packages
     artifacts.
   - `src/agents/routes.ts` exposes create, status, cancel, and artifact routes.
5. **Observability and operations**
   - `src/monitoring/` owns memory-only request usage and `/monitor`.
   - `scripts/` owns canary, health, rollout, release, and security gates.
   - `tests/` is the executable contract for the layers above.

## Request Flows

Model API request:

```text
client -> API-key middleware -> optional rate limit -> JSON parser
       -> model-prefix router -> provider adapter -> upstream OAuth API
       -> normalized response/stream -> usage tracker -> client
```

Agent Runs request:

```text
client file bundle -> auth and limits -> safe temporary workspace
                   -> fixed CLI runner -> output + Git diff + artifacts
                   -> status/poll/download API -> client review and apply
```

Agent Runs never accepts a caller-owned host path. Uploaded content is copied
into a CCPA-owned workspace under `agents.runs-dir`.

## State And Storage

- Claude account tokens live under `auth-dir`, normally `~/.ccpa`.
- Codex auth normally lives at `~/.codex/auth.json`.
- Grok OAuth normally lives at `~/.grok/auth.json`.
- Usage and recent-request data are in memory and reset on restart.
- Agent run workspaces and artifacts live under `agents.runs-dir`. The manager
  prunes completed runs registered in the current process according to
  `agents.keep-runs`; it does not scan run directories left by an earlier
  process after restart.
- `dist/build-info.json` is generated by `npm run build` and is exposed as
  non-sensitive build identity through `/health`.

## Trust Boundaries

- CCPA assumes trusted operators and clients; it is not multi-tenant.
- API keys protect `/v1` and `/admin`, but network exposure still needs an
  external trust boundary.
- Agent Runs is disabled by default and must not be exposed to untrusted
  networks.
- File paths are constrained to the temporary workspace, VCS metadata paths
  are rejected, and Git hooks/external config are disabled for diff creation.
- Codex and Grok runners use explicit sandbox modes. Claude Code receives a
  restricted tool allowlist but does not currently have a CCPA-managed OS
  sandbox profile.

## Extension Points

- Add or remove exposed model IDs in configuration; use source changes only
  when routing or translation behavior changes.
- A new provider belongs behind the provider interface and model router.
- A new Agent Runs runner needs a fixed server-side command template, config
  normalization, validation tests, route tests, and a reviewed sandbox model.
- New operational behavior should have a fixed script and an ops test instead
  of being documented as an ad-hoc shell sequence.

## Verification Surfaces

- `./scripts/verify.sh`: typecheck, unit tests, and operations tests.
- `./scripts/smoke.sh`: smoke suite.
- `npm run canary`: low-cost live readiness.
- `npm run release:verify`: strict live release contract.
- `python3 scripts/check-harness.py`: required agent-harness files.

See [docs/QUALITY.md](docs/QUALITY.md) for change-specific verification.
